# Project Operating Instructions

## Planning & QA Unified Document Rule

Effective date: 2026-09-22
Version: OPS-DOC-001

1. 기획서와 QA 관련 문서는 분리 관리하지 않고 **하나의 통합 문서**로 관리한다.
2. 통합 문서에는 다음 상태를 모두 함께 기록한다.
   - 작업 예정 / TODO
   - 작업 중 / IN PROGRESS
   - 작업 완료 / DONE
3. 작업이 시작되면 기존 항목의 상태를 작업 중으로 갱신하고, 완료 시 같은 항목을 작업 완료 상태로 전환한다. 완료했다고 별도 문서로 분리하지 않는다.
4. QA에서 발견된 결함, 재현 조건, 원인, 수정 계획, 수정 진행상황, 검증 결과를 모두 동일 문서 안에 누적 기록한다.
5. 관리자 기능, 프론트엔드, 백엔드, API, 배포/승격, 반응형 UI 등 프로젝트 범위의 QA 결과도 동일 통합 문서에서 관리한다.
6. 각 작업은 순서와 버전을 부여하고 내부 업데이트 내역 및 GitHub 업데이트 내역과 연결한다.
7. 기획서는 초안으로 취급하며 작업 시작 전과 작업 중간에 GitHub 최신 문서를 다시 확인한다.
8. 중복 기획서·중복 QA 문서가 생성되지 않도록 기존 통합 문서를 우선 갱신한다.

## Status Convention

- TODO: 작업 예정
- IN PROGRESS: 작업 중
- BLOCKED: 장애/의존성으로 진행 중단
- DONE: 구현 및 QA 검증 완료
- REOPENED: 완료 후 재발견되어 재작업 필요

## Document Maintenance

기획 변경, QA 결함, 수정 진행, 완료 검증은 모두 통합 문서의 해당 작업 항목 아래에 시간순으로 추가한다. 별도의 완료 보고서가 필요한 경우에도 원본 통합 문서의 작업 항목과 버전을 반드시 참조한다.
