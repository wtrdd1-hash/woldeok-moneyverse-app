# 전 에이전트 개발·테스트 강제 규정 — v2026.11.26.TESTGATE.1
[English canonical](ALL_AGENT_TEST_GATE_v2026.11.26.1.md) | 2026-11-26 KST
GPT/Codex, Gemini, Claude, 자동 개발·QA 및 웹/Android 양쪽 저장소에 적용한다. 기존 엄격한 Test 규정과 금융·보안·운영 승인 규정을 강화하며 완화하지 않는다. 문서 등록과 실제 시스템 강제 적용은 구분한다.

## G0~G9 필수 관문
- G0 권위: 시작·중간·후보 게시 전·승격 전 최신 원격 main, 통합기획, 세부 명세, PR, 작업기록, 보안/배포 규정을 확인하고 정확한 SHA 기록. 변경 시 충돌 해결 및 영향받은 테스트 재실행.
- G1 소유권: 작업 ID, 에이전트, 경로/API/마이그레이션 범위, 기준 SHA, 버전, 소유권 기록. 독립 브랜치/worktree, 타인 작업 수정·main 강제 Push·마이그레이션 번호 중복 금지. 충돌 시 인계하거나 독립 범위 진행.
- G2 스킬: 관련 Superpowers·보안·도메인·테스트·검증 스킬 명시 호출/읽기 및 실제 적용 근거 기록. 토큰 절감은 품질과 보안 검증 생략의 이유가 될 수 없다.
- G3 구현: 실제 API/DB·권한·금융 원장 기준, 가짜 성공·고정 데이터·권한 우회·운영 데이터 사용·비밀 GitHub 등록 금지. 회귀/부정 테스트, 계약·기존 동작 및 승인 UI, 영어 기본·한국어 두 번째 유지.
- G4 빌드/CI: 정확한 후보 커밋으로 해당 빌드, lint/typecheck, 단위/통합, 비밀·SAST·SCA·의존성·마이그레이션 검증. 총수/실패/스킵 기록. 필수 스킵/미확인은 HOLD. 실제 합성 PostgreSQL, 웹 브라우저, Android 에뮬레이터/기기 검증. 운영 변경 테스트 금지.
- G5 후보: 작업 브랜치 커밋/Push/PR, 시작·중간·종료 KST, 버전 및 EN/KO 업데이트·테스트·롤백 기록. 정확한 전체 SHA, 산출물 해시, 의존성/마이그레이션 버전, Test 환경 식별. 이전 CI나 브랜치 이름을 증거로 대체 금지.
- G6 격리 staging: Test 백엔드/프론트/DB/계정/캐시/큐/시크릿/소켓/예약/외부연동 독립성 확인. 미확인 또는 운영 접근 가능 시 차단. 불변 산출물만 배포, 실제 서비스/데이터 출처 증명.
- G7 독립 QA: 작성자와 독립된 검토자가 인증 회원/관리자 권한, CSRF·세션·IDOR, API/DB, 원장·멱등성·동시성(해당 범위), 보안, PC/모바일/다국어 및 앱 호환성 검증. 실제/기대 결과와 경로 수·실패 기록. 범위별 통과와 미완료 구분. 자기 승인 금지.
- G8 공식 Test 자동 반영: G0~G7을 통과한 코드 후보는 Test에 반영해야 완료. 단일 배포 담당은 현재 활성 자동 QA 또는 명시 인계된 대체 담당자; 중지된 QA2와 동시 실행 금지. 다른 에이전트는 후보만 등록. staging·전환·검증·롤백 전체 공통 배타 잠금 및 기존 모든 배포 경로 참여 검증, 미확인 시 HOLD. 잠금 우회/강제 해제 금지. 이전 정상 산출물 보존, 원자적 Test 전환, 외부 TLS 및 실제 제공 SHA/해시, smoke·인증 회귀 재확인. 실패 시 Test만 롤백 후 재검증. SHA 변경 시 재검증. Push만으로 배포 주장 금지. Android만 변경 시 Test 호환 APK/테스트 산출물 게시 및 SHA 검증; 서버 변경 불필요. 앱 API 변경은 일치하는 서버 Test 증거 필수. 문서 변경은 배포 제외.
- G9 운영: 독립 검토, 전체 릴리스 관문, 동일 검증 산출물, 마이그레이션·롤백 계획 및 별도 사용자 승인 후 무중단 승격. 운영 자동 배포·직접 main 변경·관리자 우회·무승인 데이터 변환·자격증명 교체·운영 재시작 금지. 범위별 Test 통과는 전체 운영 승인 아님.

## 실패·완료 규정
STARTED → CODE_READY → CI_VERIFIED → STAGED → QA_VERIFIED → TEST_DEPLOYED_SCOPED/FULL 또는 HOLD/BLOCKED/TEST_ROLLED_BACK. 적용되는 G0~G8 증거 없으면 개발 완료 금지. 문서 DOCUMENTED, 기획 PLANNING. Test 외부 TLS 및 실제 backend/DB/버전 검증 필요; 불일치는 정정 후 재검증. Critical/High 취약점, 운영 혼입, 금융 무결성, 비밀 노출, 필수 테스트 실패, SHA 불일치, 잠금·독립 검토·롤백 미확인은 배포 차단. 해당 작업 범위를 수정 후 재검증하며 독립적인 안전 작업은 계속 가능.
## 기록·공통 적용
KST 시작/중간/종료, 담당/버전/브랜치/PR, 기준·후보 SHA, 스킬 및 적용 근거, 검증 수치, 해시, 격리·잠금 증거, 이전/신규 Test 버전, 독립 검토자, 결과·롤백·차단 사유. 민감 내부 기록은 MiniPC에만, GitHub는 비식별 EN/KO. 모든 자동 예약은 매회 읽는다. 중지 예약은 임의 활성화 금지. 기존 운영 자동 승격 지시 또는 현행 아키텍처와 충돌하는 예약 문구는 이 규정과 최신 권위 문서가 우선. 실제 CI·잠금·배포 강제 여부는 별도 검증 전 완료 주장 금지.
