# v2026.09.14.80 내부 API 정합성 감사

## 감사 범위

백엔드 GitHub의 실제 Controller/Repository 계약과 Android의 Retrofit/Repository/ViewModel/Compose 호출을 대조했습니다. 기획서는 Living Spec으로 다시 확인했고 서버 권한형 경제 원칙을 유지했습니다.

## 확인된 주요 원인

- 근무 서버는 구현돼 있었지만 Android가 읽기 전용 화면으로 막혀 있었습니다.
- 웹은 Store 2.0 `/shop/catalog`을 사용하지만 Android는 구형 `/shop/items`와 잘못된 직접 배열 응답을 사용했습니다.
- 주식과 시즌은 서버가 래퍼 객체를 반환하지만 Android가 직접 배열로 해석했습니다.
- 사업 정산과 카지노 플레이에서 서버 필수 멱등성 키가 Android 요청에 빠져 있었습니다.
- 게시판 이미지 서버 계약이 Android 게시글 작성에 연결되지 않았습니다.
- 게시판 댓글/홈 공지의 응답 래퍼가 Android 선언과 달랐습니다.
- 서비스 상태는 `operational`인데 앱이 `OPERATIONAL`만 정상으로 판단했습니다.

## 수정 원칙

Android가 경제 규칙을 재구현하지 않고 서버의 권위 있는 응답을 표시합니다. 금액/보상/가격/정산/카지노 결과는 서버 영수증 또는 후속 GET으로 동기화합니다. 쓰기 요청은 세션, CSRF, 멱등성 계약을 유지합니다.

## 배포 게이트

최종 브랜치 SHA의 Android CI에서 단위 테스트, Debug APK, Release AAB가 모두 성공해야 병합합니다. 원격 개발 장치가 오프라인인 동안 GitHub Actions를 공식 빌드 게이트로 사용하고, 장치 복귀 후 같은 main SHA의 로컬 빌드를 재확인합니다.
