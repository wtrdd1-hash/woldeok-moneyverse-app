# Mandatory all-agent development and Test gate — v2026.11.26.TESTGATE.1
**English canonical** | [한국어](ALL_AGENT_TEST_GATE_v2026.11.26.1.ko.md)
Owner direction 2026-11-26 KST: applies to GPT/Codex, Gemini, Claude, human-assisted and scheduled development/QA in both Moneyverse repositories. This extends the existing strict Test governance, not a replacement for business rules, security boundaries or owner approval of Production. Runtime enforcement is a separate verifiable fact.

## G0–G9 (no exceptions by model, task size, or token budget)
- G0 AUTHORITY: fetch remote main and read latest document authority, integrated master/project plan, applicable specs, security/release rules, current PRs and worklogs at start; recheck main and competing PRs at midpoint, before candidate publish and before promotion. Record exact SHAs. If changed, reconcile without dropping work; invalidated evidence must be rerun.
- G1 OWNERSHIP: register task ID, agent, paths/API/migration scope, base SHA, version and lease. Independent branch/worktree per task; never change another agent's branch, force-push main, or silently reuse a migration number. One publisher at a time. If overlap, hand off or choose disjoint work; do not merge or deploy conflicting candidates.
- G2 SKILLS: explicitly read/invoke relevant Superpowers, security, domain, testing and verification skills; record skill, action and evidence. Use scoped search and log summaries to save tokens, never omit failures or security/financial proof.
- G3 IMPLEMENT: real backend/database/API truth; no mock success, invented amounts, permission bypass, production-data fixture, direct production writes, secret in GitHub. Write negative and regression tests; preserve existing behavior, contracts, EN canonical/KO second and approved UI.
- G4 LOCAL/CI: exact candidate commit must pass applicable build, lint/typecheck, unit/integration, secret/SAST/SCA, dependency and migration checks. Record counts and skips; no waived required tests or unsupported PASS. Any skipped required check = HOLD. Use real synthetic PostgreSQL for finance/permissions, real browser for web, emulator/device for Android. Do not run mutating tests on Production.
- G5 PUBLISH CANDIDATE: commit/push task branch and PR with start/mid/finish logs, version, sanitized EN/KO updates, test evidence, scope and rollback. Candidate identity includes full source SHA(s), artifact digest(s), dependency/migration versions and Test environment identity. Never substitute branch name or old CI result for exact SHA.
- G6 ISOLATED STAGING: verify independent Test backend, frontend, DB, accounts, cache, queues, secrets, socket rooms, scheduled jobs and outbound integrations; fail closed if unknown or Production access possible. Deploy immutable artifacts to isolated staging, not a shared dirty worktree. Prove actual Test services, route ownership and data provenance; health alone is insufficient.
- G7 INDEPENDENT QA: reviewer independent of author validates actual authenticated member/admin permissions, CSRF/session/IDOR, affected API and DB contracts, ledger invariants/idempotency/concurrency where relevant, security checks, PC/mobile UI and locale coverage, Android compatibility where impacted. Record expected/actual, exact SHA, route/fixture counts and failure evidence. A scoped PASS must explicitly list scope and remaining OPEN routes. No self-certification or hidden failures.
- G8 OFFICIAL TEST PUBLISH: automatic Test-only publication is required for eligible code candidates after G0–G7. Designate one QA publisher (active Moneyverse automatic QA, or explicitly handed-off replacement; paused QA2 must not race it). All agents submit immutable candidates; no independent shared-Test switch. Publisher must acquire a single common exclusive host lease covering stage/switch/verify/rollback, verify all existing deploy paths participate, and fail closed if that is not proven. No lock bypass, force unlock or competing publisher. Keep previous known-good artifact and independent rollback. Atomic Test switch, external TLS, exact served source/artifact receipt, smoke and affected authenticated regression recheck. On failure, rollback Test only, recheck previous baseline and record HOLD/ROLLED_BACK. A changed SHA requires fresh checks. GitHub push alone never means deployed. For Android-only changes, publish verified Test-compatible APK/test artifact with exact SHA; no unnecessary server switch. If app API changes, require matching server Test receipt. Docs-only changes never deploy runtime.
- G9 PRODUCTION: separately authorized by owner after independent review, G0–G8 evidence, full required release gates, exact accepted artifact and migration/rollback plan. No automatic production deploy, direct main update, admin bypass, unapproved data conversion, production credential rotation, or production restart. Preserve existing stricter rules. Zero-downtime with explicit rollback and post-switch verification. A scoped Test pass is not blanket Production approval.

## Status and stop rules
Use STARTED → CODE_READY → CI_VERIFIED → STAGED → QA_VERIFIED → TEST_DEPLOYED_SCOPED/FULL; or HOLD/BLOCKED/TEST_ROLLED_BACK. Never label code DONE until the applicable G0–G8 evidence exists; report code-only separately. Docs-only = DOCUMENTED; planning-only = PLANNING. An approved external Test URL and healthy backend are required; if health/identity routes conflict, reconcile rather than fabricate. If a gate fails, fix in owned branch, repeat impacted gates; continue independent safe work without waiting where possible. Critical/High security, cross-environment leakage, financial integrity, credentials, failed required tests, mismatched SHA, missing lease, unverified rollback or missing reviewer block publication. No publishing secrets, actual member data or raw sensitive logs.
## Evidence / handoff
Every stage records KST, task/agent/version, branch/PR, base/head, skill applied, changed scope, CI/test counts, artifact hash, isolation and publisher lease proof, old/new Test identity, independent reviewer, exact release outcome, rollback and blockers. Internal details stay on MiniPC; GitHub gets sanitized EN/KO. Scheduled tasks must read this policy on every run; existing prompts that imply automatic Production promotion or frontend architecture contrary to current authority are superseded. Paused jobs remain paused. No policy document alone proves CI, deployment locks or runtime enforcement; verify actual configuration before claiming enforced.
