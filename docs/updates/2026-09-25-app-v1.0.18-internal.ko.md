## 기준점
- 작업 시작 앱 main: `dfe24bac1886e2b63b9b736005e4d9884074ac5d`.
- 작업 시작 서버 기획 기준: `99b0eaa04bbd0b28005861c624690c56744e8a14`; 중간 서버 main은 `e51d0bdcd5ab9e398898c28f9842f611e3443454`까지 전진했습니다.

## 구현
- 현재 모바일 계약에서 `AppCapabilityCatalog` 생성: 전체 179개, 관리자 11개, 회원 168개.
- GET/POST/PUT/DELETE, path/query/body 입력, 파괴적 작업 확인, 안전한 응답 미리보기를 지원하는 계약 기반 실행 계층을 추가했습니다.
- 회원 전체 기능 허브와 관리자 전용 기능 섹션을 추가했습니다.
- 사용자 UI의 route/address 표시 및 route가 포함될 수 있는 진단/오류 출력을 제거했습니다.
- debug는 `test.easy-scraping.com`, release는 `easy-scraping.com`에 고정했습니다. 이 값은 구현 설정이며 사용자 화면에는 표시하지 않습니다.
- `AppCapabilityCatalogTest`를 회귀 gate로 추가했습니다.

## 증거 및 남은 gate
- 정적 기능 수: 고유 계약 기능 179개.
- Test gateway smoke: health 200, contract metadata 200, auth policy 200, game clock 200, 비인증 관리자 접근 401.
- Test 웹 루트는 500을 반환했으며 앱 BFF 장애가 아닌 별도 Test 웹 루트 결함으로 기록합니다.
- 계약 metadata는 아직 `v2026.09.22.359`를 반환하며 endpoint 생성 수는 현재 179개입니다. metadata drift는 서버 후속 과제입니다.
- Debian 호스트에 Android SDK가 없어 로컬 Gradle 검증은 환경 차단됐고, Android 36을 설치하는 GitHub Android CI를 이 브랜치의 실제 빌드/테스트 권위로 사용합니다.
- 인증된 관리자 runtime 검증과 필수 전체 화면/반응형 5회 QA가 남아 있습니다. 해당 gate 통과 전까지 PR #25는 draft로 유지합니다.
