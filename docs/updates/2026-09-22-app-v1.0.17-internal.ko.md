- `MobileApiContractTest.kt`: 범용 HTTP verb 계약 회귀 테스트 추가.
- `app/build.gradle.kts`: versionCode 18 / versionName 1.0.17.
- `./gradlew testDebugUnitTest lintDebug`: 성공.

## 배포 게이트
- 실제 운영 데이터에 쓰기 요청을 보내는 검증은 금지하고 비파괴 endpoint만 스모크한다.
- 격리 테스트 서버가 정상 확인되어야 운영 승격 가능하다.
- 2026-09-22 재확인: `staging.moneyverse.wtrdd1.com` DNS 해석 실패, 스테이징 HTTP 검증 불가.
- 운영 비파괴 확인: `/app-api/v1/content/status` HTTP 200, `/app-api/v1/auth/providers` HTTP 200.
- 따라서 브랜치/PR 상태로 유지하고 테스트 서버 복구 전 운영 main 승격은 보류한다.

## QA 후속 수정 — APP-API-UNIVERSAL-002
- PR 리뷰/QA에서 사용자 지정 `Accept` 헤더가 덮이는 문제를 발견하고 수정했다.
- HTTP, telemetry, lobby realtime, market realtime에서 서로 다른 앱 버전을 광고하던 문제를 수정했다.
- 앱 버전 식별자는 `ApiClient.APP_VERSION = 1.0.17`로 일원화했다.
- `ApiClientRequestTest`를 추가해 사용자 지정 Accept 보존과 User-Agent 버전 일치를 회귀 테스트로 고정했다.
- 재실행 결과: `testDebugUnitTest lintDebug assembleDebug` BUILD SUCCESSFUL.
- 운영 스모크: status/providers/policy/viewer/public catalog/public board 정상, 인증 필요 경로는 익명에서 401 정상.
- 제한: 원격 개발 장치에 `adb`가 없어 실제 단말/에뮬레이터 설치 QA는 이번 실행에서 수행하지 못했다.
