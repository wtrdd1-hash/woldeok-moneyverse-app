# v2026.09.14.77 — Mobile API Contract Compatibility

## English

This update aligns the Android app with the current Woldeok Moneyverse mobile BFF contract under `/app-api/v1` while preserving existing UI behavior.

### Changes

- Added a network-boundary compatibility interceptor for canonical response envelopes and field aliases.
- Corrected canonical request bodies for loans, casino plays, business settlements, board posts/comments, privacy requests, business purchases, shop purchases, and wallet transfers.
- Added automatic idempotency keys where the server contract requires them.
- Preserved binary image/media responses without JSON conversion.
- Added CSRF token refresh handling and explicit JSON/Android request headers.
- Separated sign-in pre-session creation from consent persistence.
- Added generic transport support for GET, POST, PUT, DELETE with/without a body, and raw-byte POST requests.
- Added Android GitHub Actions CI and MockWebServer contract regression tests.

### Contract baseline

- Backend repository: `wtrdd1-hash/Woldeok-Moneyverse-Migration`
- Backend main rechecked during QA: `d66e247`
- Mobile schema reference remains: `v2026.09.14.76`

### QA verification

- Pull request #1 latest QA-verified head: `db2bdfa`.
- Android CI run #22 passed, including the expanded contract regression suite, `testDebugUnitTest`, and `assembleDebug`.
- Live production BFF checks passed for auth providers, prelogin session creation, policy retrieval, viewer state, Google mobile authorize URL generation, and Discord mobile authorize URL generation.
- Public production endpoints checked successfully: content status, public shop catalog, and public board posts.
- Anonymous access to wallet, profile, stock portfolio, owned businesses, and private photo submissions correctly returns HTTP 401.
- Source search found no `TODO`, `FIXME`, `NotImplemented`, or `UnsupportedOperationException` markers.

### Known QA issues

- `GET /app-api/v1/content/status` returns HTTP 200 but currently reports `state:"unknown"` for web, API, and database sources. Transport is healthy, but monitoring data is not sufficient to classify those components as healthy.
- The configured staging hostname `staging.moneyverse.wtrdd1.com` currently does not resolve, so a real staging deployment/E2E gate is unavailable.
- Destructive/authenticated write endpoints were not executed against production data. Their request/response compatibility is covered by MockWebServer regression tests instead.

### Release gate

Unit tests, debug assembly, and non-destructive production BFF smoke checks are passing. Remaining external blockers are the unresolved staging hostname and the `content/status` monitoring values remaining `unknown`.
