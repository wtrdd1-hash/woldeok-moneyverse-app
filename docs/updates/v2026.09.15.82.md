# v2026.09.15.82 — Stock market and business purchase reliability

## Summary

This update fixes the mobile economy screen's stock-list parsing path and improves write reliability for stock orders and business purchases.

## Changes

- Accept both the canonical `{ "stocks": [...] }` envelope and the app compatibility interceptor's normalized `[...]` stock response.
- Round stock percentage changes to two decimal places at the runtime adapter boundary.
- Make stock detail gain/loss status visually explicit with `▲/▼`, percentage, and `gain/loss` wording.
- On HTTP 403 during a stock order or business purchase, refresh the authenticated viewer/CSRF state and retry once using the same idempotency key.
- Keep the canonical business purchase endpoint: `POST /app-api/v1/businesses/catalog/{id}/purchases`.

## Root cause

The server returns the stock list as an envelope. The compatibility interceptor unwraps it to an array for the legacy typed API, while the runtime economy repository attempted to parse the already-unwrapped response as an object again. That second unwrap raised a JSON shape error and left the stock screen without a list.
